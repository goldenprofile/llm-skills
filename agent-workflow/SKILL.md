# Agent Workflow

Навык про то, **как вести работу с агентом**, а не про содержимое кода. Пять
режимов — стадии одного цикла: решить → разбить → сформулировать → провести
сессию → отрефлексировать.

## Шаг 0. Выбери режим

| Режим | Вопрос пользователя | Куда дальше |
|---|---|---|
| **delegate** | «сам или агент», «какой режим/модель», «почему агент справился плохо» | [references/delegation.md](references/delegation.md) |
| **decompose** | «разбей задачу», «слишком большая», «с чего начать фичу» | [references/decomposition.md](references/decomposition.md) |
| **prompt** | «улучши промт», «сформулируй задачу для агента» | [references/prompt-craft.md](references/prompt-craft.md) |
| **context** | «новая сессия или продолжаем», «ты забыл», «что положить в CLAUDE.md» | [references/context.md](references/context.md) |
| **audit** | «проверь себя», «что устарело», «какие ошибки повторяешь» | [references/self-audit.md](references/self-audit.md) |

Режимы часто идут подряд: крупная задача — это обычно delegate → decompose →
prompt. Не гони через все пять, если спрошено про один; но если выбранный режим
явно не тот (просят «улучши промт» на задаче, которая не влезет в один заход) —
скажи об этом и предложи начать с decompose.

## Сквозные принципы

**Размер куска решает больше, чем формулировка.** Самая частая причина плохой
работы агента — не «плохой промт», а кусок, который не проходит тест одного
захода. Проверь размер прежде, чем полировать текст.

**Разведка отделена от изменений.** Агент, который одновременно изучает и
правит, изучает плохо и правит наугад. Разведку — отдельным куском, лучше
сабагентом: в основной контекст вернётся вывод, а не двадцать прочитанных файлов.

**Что должно пережить сессию — пишется в файл.** План, решения, найденные
факты. Договорённость, живущая только в диалоге, исчезает при компактификации.

**Контекст — исчерпаемый ресурс.** Всё, что лежит в нём постоянно (CLAUDE.md,
описания навыков), стоит токенов в каждой сессии. Клади туда только то, что
модель не выведет сама из структуры проекта.

**Требования — не делегируются.** Агенту можно поручить *уточнение* требований
вопросами, но не *выбор* за пользователя. «Сделай как лучше» даёт среднее
по интернету.

## Границы навыка

- `session-catchup` — возобновить прерванную работу (восстановление, а не рефлексия).
- `harness-engineering` — построить обвязку проекта: Makefile, CI, ARCHITECTURE.md, DoD.
- `spec-writer` — документ-план с фазами, оценками и рисками (decompose даёт рабочий
  список кусков, а не документ).
- `goal-pipeline` / `ratchet-loop` — автономное исполнение фаз и оптимизация метрики.
- `llm-feature-architect` — LLM внутри вашего продукта, а не в вашей работе.
- `change-review` — второе мнение о полученном коде.

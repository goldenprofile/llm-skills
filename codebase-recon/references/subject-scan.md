# Режим subject — адресный разбор одной области

**Вход:** `subject` (обязательно) — что изучаем: «аутентификация и авторизация»,
«как parking-модуль обрабатывает SSL», «система уведомлений», «обработка платежей».
`goal` (опционально) — желаемое состояние: «все сертификаты через Let's Encrypt
с авто-обновлением», «API соответствует OpenAPI 3.0», «покрыт критический путь».

## Фаза 1. Разведка subject

Найти все файлы и модули, связанные с subject.

Сначала — два независимых поиска **параллельно** (один вызов, оба инструмента):

- **Glob** — файлы по имени: паттерны, связанные с subject (`**/*auth*.py`,
  `**/notifications/**`).
- **Grep** — по содержимому: ключевые термины subject
  (`output_mode: files_with_matches`, при необходимости `content` с контекстом).

Затем — **Read** найденных ключевых файлов (зависит от результатов поиска,
поэтому идёт следующим шагом): «как реализован subject?».

Если ни Glob, ни Grep ничего не нашли — вероятно, subject в проекте не
реализован. Это валидный результат: скажи прямо (при наличии goal все
требования попадут в статус GAP).

### Что искать — по стекам

| Артефакт | Django | FastAPI | aiogram |
|----------|--------|---------|---------|
| Модели/данные | `class.*Model`, `models.py` | `class.*Base` (SQLAlchemy), `models.py` | модели БД, если есть |
| Схемы/контракты | `serializers.py` | Pydantic-схемы (`class.*BaseModel`), `schemas/` | — |
| Точки входа | `views.py`, `viewsets.py`, `@api_view` | `APIRouter`, `@router.(get\|post)`, `app = FastAPI()` | `Router()`, `@router.message`, `@dp.message` |
| Роутинг | `urls.py`, `urlpatterns` | `include_router`, префиксы роутеров | `Router`, `dp.include_router` |
| Сервисы/логика | `*_service.py`, `services/`, `*Service` | `services/`, зависимости `Depends(...)` | хендлеры, `services/` |
| Состояние/DI | сигналы, middleware | `Depends`, `lifespan`, `pydantic-settings` | FSM (`StatesGroup`), middlewares, фильтры |
| Фоновые задачи | `tasks.py`, `@shared_task`, `@app.task` | `BackgroundTasks`, Celery/ARQ | polling-воркер, планировщики |
| Тесты | `test_*.py`, `tests/`, `conftest.py` | то же + `httpx`/`TestClient` | то же + мок `Bot`/`Dispatcher` |
| Шаблоны/UI | `templates/`, `*.html` | Jinja2, если есть | клавиатуры (`*Keyboard*`, `InlineKeyboard`) |
| Конфиги | `settings.py`, `.env` | `pydantic-settings`, `.env` | `.env`, конфиг бота/токена |
| Миграции | `migrations/` | Alembic (`versions/`, `alembic.ini`) | Alembic, если есть БД |
| CLI | `management/commands/` | `click`/`typer`, `if __name__ == "__main__"` | `if __name__ == "__main__"` |

**Результат фазы:** список ключевых файлов с ролью каждого в одну строку.

## Фаза 2. Экспресс-анализ

Как это работает сейчас. Прочитай ключевые файлы из фазы 1 и определи:

1. **Структура модулей** — какие задействованы, как связаны (импорты, зависимости).
2. **Точки входа** — проследи цепочку до данных: Django `URL → View → Service → Model`;
   FastAPI `router → Depends → service → модель`; aiogram `Router → handler → FSM/service`;
   плюс CLI, management-команды, фоновые задачи, сигналы и middlewares.
3. **Поток данных** — откуда приходят, как обрабатываются, куда сохраняются.
4. **Внешние зависимости** — сторонние сервисы и API, библиотеки под subject,
   инфраструктура (БД, кэш, очереди).

**Правило глубины:** читай только то, что непосредственно связано с subject.

## Фаза 3. Gap-анализ и план

Выполняется всегда, формат зависит от наличия goal.

**Если goal указан:** декомпозируй его на проверяемые требования и присвой
каждому статус — **OK** (реализовано), **PARTIAL** (частично), **GAP**
(отсутствует), **RISK** (есть, но с проблемами). Затем — план закрытия gap-ов.

**Если goal не указан:** карта + наблюдения (не полноценный аудит — для этого
`python-project-audit` / `django-audit` / `change-review`): что есть и как
связано, очевидные риски, точечные рекомендации в рамках subject.

## Формат вывода

```markdown
## Subject: [тема анализа]

### Текущее состояние

**Ключевые файлы:**
- `path/to/file.py:42` — [роль файла, 5-10 слов]

**Архитектура:**
[какие модули, как связаны, поток данных]

**Зависимости:**
- Внутренние: [модули проекта]
- Внешние: [библиотеки, сервисы]

### Gap-анализ

| # | Требование | Статус | Комментарий |
|---|------------|--------|-------------|
| 1 | ...        | OK     | ...         |
| 2 | ...        | GAP    | ...         |

**Итого:** X из Y требований выполнено, Z gap-ов.

### План действий

1. **[HIGH/MEDIUM/LOW]** — описание действия
   - Файлы: `path/to/file.py`
   - Что сделать: [конкретно]
```

# Как читать вывод экстрактора

Экстрактор отдаёт частоты, а не решения. Решения принимаются здесь.

## Веса, а не количества

Числа рядом со значениями — **веса**, и они разные по смыслу:

- цвета фона и рамок взвешены по **площади** (полноэкранный фон обязан
  перевесить двести мелких `span`);
- цвет текста, семейство, кегль, вес, интерлиньяж — по **объёму текста**;
- радиусы, отступы, `gap`, тени — простые **счётчики вхождений**.

Поэтому «`#0f1011` — 4016» не значит «4016 элементов»: это доминирующий фон.

## Базовая единица и шкала отступов

Возьми `padding` и `gap`, отсортируй по частоте, посмотри на НОД верхушки.
Если ведущие значения кратны 4 (4/8/12/16/24/32) — базовая единица 4px и
дизайн-система есть. Если в верхушке сидят 15, 13, 9, 7 — сетки нет, значения
подбирались на глаз. Это самая полезная одна цифра во всём выводе.

Единичные крупные значения (96, 128) — это вертикальные отступы секций, а не
шкала компонентов; выноси их отдельной строкой «ритм секций».

## Шкала кеглей

Плотная группа в узком диапазоне плюс редкие крупные значения — нормальная
шкала (текст 12–15, заголовки 24/32/48). Семь-восемь размеров, идущих подряд
без разрывов (16,19,20,21,22,26) — шкалы нет, каждый блок верстался отдельно.

Веса смотри вместе с семейством: `510` и `590` — вариативный шрифт, такие
значения по скриншоту не восстанавливаются. Обычный статический шрифт даст
300/400/600/700.

## Радиусы

`9999` в выводе означает «полностью скруглённый» — либо `border-radius: 50%`
(аватар, кружок), либо pill-кнопка. Экстрактор нормализует и проценты, и
заведомо большие пиксельные значения к одному ключу.

## Кластеры компонентов

Компоненты определяются НЕ по классам — у Tailwind и CSS-in-JS они
бессмысленны, — а по сигнатуре стиля:

```
tag | фон | цвет текста | радиус | padding | вес | рамка
```

Одинаковая сигнатура, встреченная N раз, — это один вариант компонента.
Три-четыре верхних кластера обычно и есть primary / secondary / ghost.
Пример реального вывода:

```
button | #d31820 | #ffffff | 2 | 20px 0px | 400 | no-border   x6   <- primary
a      |         | #2e353e | 9999 | 12.8px 32px | 400 | #2e353e x4  <- pill outline
```

Дробные значения (`12.8px`) означают, что отступ задан в `em` и зависит от
кегля, — при переносе это надо сохранять относительным, а не округлять.

## CSS-переменные

Читаются из `getComputedStyle(:root)`, а не обходом `document.styleSheets`:
у кросс-доменных таблиц `.cssRules` бросает SecurityError (на linear.app
недоступны 51 из 85 таблиц), и computed-путь при этом полнее — 417 переменных
против 265.

Много переменных с осмысленными именами (`--header-height`, `--text-large-line-height`)
= у сайта есть настоящая дизайн-система, и её можно взять почти дословно.
Мало и/или всё захешировано = систему придётся реконструировать по частотам.
Само по себе число переменных — хороший индикатор зрелости фронтенда.

## Разобранный пример: два реальных сайта

Замер 2026-08-24, вьюпорт 1440x1000.

| | linear.app | expojeweller.ru |
|---|---|---|
| Отступы (верхушка) | 8 / 24 / 32 / 12 / 6 / 4 | 15 / 8 / 4 / 6 / 13 / 9 |
| Базовая единица | 4px, соблюдается | не прослеживается |
| Кегли | 15/14/12/13, скачок 24/48 | 19/26/16/32/21/20/22 |
| Веса | 400 / 510 / 590 (вариативный) | 400 / 300 / 600 |
| `gap` | 8 / 12 / 4 | **пусто** |
| CSS-переменных | 252 | 26 |
| Контейнер | — | 1140px |

Вывод, который отсюда следует, и есть польза навыка: у второго сайта проблема
не в палитре (она вполне рабочая: `#d31820` на `#f4f4f4`), а в отсутствии
ритма — семь кеглей без шкалы, отступы вне сетки и полное отсутствие `gap`,
то есть вёрстка на отступах вместо flex/grid. Менять надо не цвета.

Формулировка «сделай как у Linear» после такого замера превращается в
конкретный список: свести кегли к шкале, положить отступы на сетку 4px,
перевести раскладку на `gap`.

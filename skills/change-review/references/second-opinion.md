# Режим second-opinion — ревью другой моделью

Ассистент не проверяет сам себя: он собирает вход, делегирует разбор модели
другого семейства и представляет её отчёт. Смысл именно в смене семейства — оно
ловит то, что автор кода структурно не видит: галлюцинации несуществующих API,
over-engineering, пропущенные импорты и граничные случаи.

## Механизм

Нужен **любой CLI, который принимает промт одной строкой и печатает ответ модели
в stdout** — без интерактивной сессии и без лишнего оформления. Подойдёт `llm`,
`aider --message`, официальный CLI провайдера или собственная обёртка над HTTP API.
Спроси у пользователя, какой инструмент настроен, или загляни в `PATH`; не
предполагай конкретный.

Примеры ниже используют `hermes` — CLI-агент, умеющий ходить в разных провайдеров;
ключ `-z` печатает **только** ответ модели. Замени команду на свою, смысл флагов
тот же:

```bash
# Модель-аудитор по умолчанию берётся из конфига CLI
hermes -z "ПРОМТ_АУДИТА_С_КОДОМ"

# Явный выбор под задачу
hermes -z "ПРОМТ" -m deepseek/deepseek-v4-pro --provider openrouter   # большой объём, глубокий разбор
hermes -z "ПРОМТ" -m z-ai/glm-5.2            --provider openrouter    # быстрый чекап диффа
```

Правила:

- **Модель-аудитор ≠ модель, писавшая код.** Писал Claude → аудирует
  DeepSeek / GLM / Kimi (и наоборот).
- **Не хардкодь версии моделей** — они устаревают. Актуальные ID спрашивай у
  самого CLI (для hermes — `hermes model`); примеры выше верны на момент написания.
- **Назови пользователю модель:** «Аудирую DeepSeek 4 Pro. Нужна другая
  (GLM / Kimi) — скажи».
- **Вход больше ~500 строк** дроби по файлам или модулям, иначе аудитор теряет
  контекст; на больших объёмах бери модель с большим окном.
- Вход собирай штатными инструментами среды: `git diff` / `git log` в терминале,
  `Read` для файлов, `Grep`/`Glob` — чтобы проверить существование API и
  паттерны проекта.
- Подходящего CLI нет — скажи прямо и предложи режим self. Не изображай второе
  мнение собой: это ровно та ошибка, ради устранения которой существует режим.

## Режимы входа

| Режим | Когда | Вход |
|---|---|---|
| **Дифф** | Claude только что внёс изменения | `git diff` — коммит, N коммитов или рабочее дерево |
| **Файловый** | проверить конкретные файлы или модуль | список путей |
| **Архитектурный** | Claude спроектировал фичу или модуль | описание архитектуры + ключевые файлы |

Глубина диффа — если не указана, спроси:

```bash
git diff HEAD~1..HEAD        # последний коммит
git diff HEAD~10..HEAD       # N последних коммитов
git diff                     # незакоммиченное
git log --oneline -10        # найти границы коммитов
```

Больше трёх коммитов — предупреди об объёме и предложи разбить на порции.

## Порядок

1. Контекст проекта (обязательный шаг из SKILL.md) — `CLAUDE.md` целиком,
   `ARCHITECTURE.md`, `AGENTS.md`.
2. Собери вход под выбранный режим.
3. Выбери линзу ([lenses.md](lenses.md); по умолчанию — Скептик) и модель,
   сообщи её пользователю.
4. Сформируй промт ([audit-prompts.md](audit-prompts.md)) и вызови
   CLI в терминале. Большой вход — по частям.
5. Представь результат по [output-format.md](output-format.md), сгруппировав
   находки по критичности. Отчёт чужой модели — не истина: находки, противоречащие
   канон-документам проекта, помечай как неприменимые и объясняй почему.

## Когда режим полезен, а когда избыточен

Полезен: изменение больше ~100 строк или затрагивает больше трёх файлов;
незнакомая кодовая база (выше риск галлюцинаций); перед деплоем; «работает, но
странно».

Избыточен: правка в одну-две строки, опечатка, конфиг, знакомый фреймворк и
меньше ~50 строк. В этих случаях режим self дешевле и достаточен.

## Типовые промахи чужого аудитора

- **Тяжёлый `save()`.** Совет `obj.save()` без `update_fields` там, где у модели
  дорогой `save()` (пересчёт полей, санитайз HTML), — частый анти-паттерн из-за
  отсутствия контекста проекта. Поэтому шаг с `CLAUDE.md` обязателен.
- **Смешение scope коммитов.** При разборе нескольких коммитов проблемы старых
  приписываются текущему — сверяйся с `git blame` по изменённым строкам.
- **Удаление «временного» alias** без проверки использования — всегда
  перепроверяй Grep'ом.

# Роли

Координатор подбирает **только нужных**. Базового состава «всегда эти трое»
нет. Две роли — нормально; больше четырёх — почти наверняка лишние.

## Каталог

| Роль | Зона | Типичные возражения |
|------|------|---------------------|
| **Backend** (Senior Python Backend Engineer) | API, домен, БД-доступ, границы слоёв, тесты ядра | overkill-стек, толстые views, sync I/O в async |
| **DevOps** | Инфраструктура, деплой, CI, сеть, секреты как файлы/env | «потом настроим», ручной SCP как процесс, секреты в репо |
| **SRE** | Надёжность, health, rollback, наблюдаемость, инциденты | нет отката, нет сигналов, миграция без бэкапа |
| **Security** (AppSec) | Threat model, аутентификация, периметр, секреты, OWASP | открытый порт «на время», токен в логах, trust к клиенту |
| **DBA** | Схема, индексы, миграции данных, бэкап/restore | смена схемы без expand/contract, нет плана отката данных |
| **QA** | Стратегия тестов, критерии приёмки, риск регрессий | «покроем потом», непроверяемые done-критерии |
| **Fullstack** | UI, UX, контракт API с точки зрения клиента | SPA без нужды, API без формы ошибки, недоступность |
| **Другая** | Узкий профиль (почта, DNS, платёжный провайдер…) | только если зона реально есть во входе |

Имена в документах — из таблицы, не выдумывай титулы. Узкую роль называй
по зоне (`SRE / Mail`), не общим «эксперт».

## Как выбирать

1. Закрой зоны линзы, не «представительство специальностей».
2. Если две роли будут говорить одно и то же — оставь одну.
3. Backend не заменяет DBA на миграции данных; DevOps не заменяет Security
   на threat model.
4. Не добавляй QA «для галочки», если нет продукта, который кто-то принимает.
5. Профиль исполнителя (один человек, без выделенного админа, лимит часов)
   — ограничение **координатора**, не повод выкинуть роль: роль всё равно
   говорит, а оценка трудозатрат учитывает, кто будет руками.

## Как вести обсуждение

Пиши `TEAM_DISCUSSION.md` как протокол, не как пьесу.

- Координатор формулирует **вопрос** (одно решение за раз).
- Каждая выбранная роль: позиция, аргумент из своей зоны, что сломается
  при чужом варианте.
- Разногласие обязательно там, где есть реальные альтернативы (стек, порядок
  миграции, глубина MVP). Если все согласились сразу — задай контрвопрос
  самой заинтересованной роли.
- Координатор **решает** и записывает ADR-lite. Не прячь отвергнутое:
  через месяц его предложат снова.
- Не голосуй «большинством». Вес — зона ответственности + ограничения входа.
- Эскалация пользователю: продуктовый выбор, вкус, то, что меняет scope
  или деньги. Инженерный спор ролей пользователю не сбрасывай, пока нет
  двух честных вариантов с ценой.

Голоса ролей — это линзы одного агента, не отдельные личности. Не имитируй
характер, не пиши small talk.
